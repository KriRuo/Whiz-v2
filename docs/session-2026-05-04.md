## 3. Bug fix: transcription never produced output

**Root cause:** Interface contract mismatch introduced during the v1 refactor.

- `core/recording_service.stop_recording()` called `self.audio_manager.stop_recording(self.current_audio_path)` expecting a file path back
- `audio_manager.stop_recording()` was refactored to take no arguments and return `List[bytes]` (raw frames)
- `recording_service` checked `if audio_path and Path(audio_path).exists()` — always `False` on a list → `RecordingResult(success=False)` → transcription never called

**Fix (`core/recording_service.py`):**
```python
frames = self.audio_manager.stop_recording()
saved = self.audio_manager.save_audio_to_file(frames, audio_path) if frames else False
if saved and Path(audio_path).exists():
```

**Commits:** `d47a5df`

## 4. Bug fix: tray icon / waveform state never changed to "recording"

**Root cause:** `speech_controller.start_recording()` never emitted a status update after successfully starting, so the UI had no signal to switch state.

**Fix (`speech_controller.py`):**
```python
if success:
    logger.info("Audio recording started successfully")
    self._update_status("Recording...")   # ← added
```

The string `"Recording..."` is the key that `speech_ui.py` uses to drive tray icon, waveform widget, and button enable/disable — all three are keyed off that exact string.

## 6. Bug fix: tray icon always showed state (loading/ready/recording)

**Problem:** Tray icon cycled through grey (loading), green (ready), red (recording) at all times. User wanted the icon to look neutral when idle and only show a distinct indicator during recording.

**Fix (`ui/system_tray.py`):**
- `state == "recording"` → red dot (16×16 painted circle, `#cc4444`)
- Anything else → restore original `app_icon_transparent.ico`

**Fix (`speech_ui.py`):**
```python
if status == "Recording...":
    self.system_tray.set_state("recording")
else:
    self.system_tray.set_state("idle")   # restores app icon
```

**Commits:** `c640462`

## 7. Bug fix: hotkey toggle mode never applied at startup

**Root cause:** `main.py` reads six settings from QSettings when constructing `SpeechController` (hotkey, model, auto_paste, language, temperature, engine) but `behavior/toggle_mode` was absent. Controller always initialized with `self.toggle_mode = False` (HOLD mode) regardless of saved setting.

**Fix (`main.py`):**
```python
controller.set_toggle_mode(settings.get("behavior/toggle_mode", False))
```
Added immediately after controller construction.

**UX fix (`ui/preferences_dialog.py`):**
Renamed checkbox from `"Toggle Mode (press once to start/stop)"` to `"Press-to-toggle mode"` with clearer help text:
- *Unchecked (default): Hold the hotkey to record — release to stop*
- *Checked: Press once to start, press again to stop*
